# 超级组织

从一条真实重复的业务开始，例如从素材到待审稿件。这里用木林 Agent 的探索提出设计问题，完成度以实际试跑为准。

1. 画出当前一单从开始到完成的路径。记录每步输入、输出、负责人和等待点。优先处理反复发生、验收口径已经能描述的工作。
2. 给每次交接写最小契约：任务目标、授权范围、必需上下文或资料引用、交付物、验收条件、异常由谁接手。让接手者只看契约和授权材料就能行动。
3. 逐项回答权责问题。个人记忆、共享知识与工作产物分别归谁，谁能读取与修改，成员离开能带走什么。每个外部动作或不可逆判断写清谁有最终决定权。
4. 让人能看到任务进行到哪一步、卡在哪里、需要谁处理。为失败记录可接手的状态与产物，重试前核对上一次是否已经产生外部效果。
5. 跑一单影子流程，对照人工结果。再交给第二个操作者从头复做，记录交接往返、等待时间、返工和决策积压。根据实际故障修契约。

交付一条业务的交接约定、记忆与权限清单、异常接手机制，以及试跑验收办法。

## 人机协作治理

人给 Agent 真实上下文、审美与价值判断，以及明确权限。Agent 回传观察证据、冲突和可行选项，指出目标与行动数据的偏离。一次呈现的待决事项要匹配人的处理能力。十个机会都符合方向时，先给能在当前窗口行动的一项，并说明选择依据。

### 交接单

- 目标与验收证据。完成以后，接手人能在哪里核对结果？
- 权限与资料。读哪些材料，可写到哪里，外部动作由谁授权？
- 当前状态。已完成的步骤、已产生的外部效果、阻塞和最后一次验证。
- 接手动作。下一步由谁做，如何判重，失败在哪一状态停止，谁接管。
- 记忆回流。哪条经验只是本次观察，哪条已被跨任务证据支持。规则晋升时附上独立试跑记录。

例如让三个 Agent 整理素材、拟稿、审查时，可以共享素材引用和草稿。审查者对事实和发布风险留下可定位的证据，只有授权人能决定发布。审查出错要能从同一草稿继续，发布超时先核查平台实际状态。试跑量度包括人工兜底次数与最长等待点。若审批仍全部堆到同一个人手里，重新划分哪些属于常规验收、哪些真正需要本人判断。
