# 可重启的 Agent 循环

源自 Vault 的 Loop Engineering 实践和工程验证规范。先用一次手工试跑证明重复任务真实存在，再决定哪些步骤适合循环。

| 项 | 写清楚 |
| --- | --- |
| 目标 | 一句话描述可观察的交付结果 |
| 固定输入 | 代表性材料、基线和当前版本 |
| 检查 | 固定评判方法、运行命令或独立验收者 |
| 证据 | 原始输出在哪，哪个指标要变，哪些行为必须保持 |
| 预算 | 轮次、时间或成本，哪个先到就停 |
| 权限 | 可读写范围、外部操作授权和异常处理人 |
| 出口 | 完成、证据不足、受阻，每种怎样复核和接手 |

先跑基线。每轮只改一个主要变量，用相同检查读结果。保留失败输出和可复核的产物。独立证据不足时，把发现记作候选经验，继续记录它在独立样本上的表现。副作用发生或检查器失效时先停，核对已有状态后再判断能否安全重试。

最后写一份可重启交接：目标、实际做过什么、最近一次可复核输出、还缺什么、权限边界和下一步。暂停后让接手人从这份交接找回进度。

虚构例子：反复改商品图提示词时，用同一组产品参考图和事先定义的保真判定比较。一次只改锚点说明。预算到期、评审不一致或已过验收，分别给出对应终止报告。
