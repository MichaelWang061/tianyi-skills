# 品牌内容系统

把一套商品内容按使用场景来设计。来源是 BrandOS 的产品化实践。

1. 先问这套素材服务哪件事，例如上新详情页、广告测试或社媒发布。拿到品牌资料、经确认的商品图、目标平台及本次交付用途。
2. 为商品写锚点。区分必须保持的特征与允许变化的部分。颜色、版型、图案、标签文字和比例以经确认的资料为准。资料缺失时标出待补的角度和尺寸。
3. 每个使用场景写一张卡，包含用途、输入、构图或动作、允许变化、交付规格和可观察的验收项。规格由用户提供或查平台官方资料。先做能覆盖高频需求的一小套。
4. 先验首张，再扩到其他场景。用同一商品锚点逐张核对，然后并排看整套的色调、比例和一致性。把问题落到具体图和字段。
5. 交付整套用途清单、可复用场景卡、验收记录及待重做项。若要判断管线是否比原做法更省，记录一套合格素材的制作工时、返工次数与成本。

示例任务（虚构）：「为一件有印花的外套做上新包。」白底主图负责认款，局部细节负责看清印花，穿搭图展示上身。三个场景共用经确认的版型与印花锚点，允许环境光和构图变化。

## 两种交付路径

先问是代交付还是客户自助。定制服务走产品图 → 团队建档 → 小样 → 客户确认 → 批量 → 按套交付。自助走上传 → 轻建档 → 匹配品类模板 → 首批产出 → 审标 → 按套下载。沿客户旅程查断点，承诺上传却没有入口、首样已做却没有确认记录、后台能批量却只能让客户逐张下载，都应落到具体交付状态。

### 场景卡与验收记录

| 字段 | 示例（虚构） |
| --- | --- |
| 动词级场景 | 展示外套袖口和印花边缘 |
| 输入 | 确认的正面照、袖口细节、印花近照 |
| 锁定项 | 版型、印花位置和形状、颜色、标签 |
| 可变项 | 构图、背景、光线 |
| 输出 | 指定平台的细节素材，规格由用户确认 |
| 验收 | 印花无缺字或变形，袖口结构与参考一致，有任何偏差则标出图片和字段 |

同一产品变体独立记录锚点。出错先追参考图和场景卡，明确是产品信息错、图片本身漂移，还是审美偏好尚未决定。小样通过后记录谁确认了哪一版，再批量复用。整套交付要有可辨认的版本、用途目录、确认或返工记录。要决定下一批模板做什么，先统计客户实际用到的场景和每种失败耗费的返工时间。
